# Unscrambler non-design data

> **Status:** Supported (scoped) · **Vendor:** CAMO / The Unscrambler · **Extension:** `.00D` · **Feature flag:** none

The native Rust reader handles the Unicode, little-endian **binary revision 35**
of Unscrambler non-design data files. Detection uses the embedded
`Non-design data File Generated by The Unscrambler` signature, independent of
the extension. In-memory and filesystem reads use the same decoder, including
in builds without optional format features.

## File structure

The observed layout has a 768-byte file header followed by ten ordered blocks
1000–1009. Each block starts with four little-endian 32-bit integers: type,
identifier, element count and stride. These blocks contain the dataset header,
settings, row/column descriptors, sample/variable selections, UTF-16LE labels,
dataset label and a column-major float32 matrix. Dimensions, block lengths,
layout types and selection bounds are validated before mapping. The dataset
offset is read from the file header. See the
[reverse engineering report](unscrambler-reverse-engineering.md) for byte offsets,
evidence, numerical tolerances and remaining unknowns.

## Extracted records

- One record per matrix row, preserving order and duplicate sample identifiers.
- Disjoint leaf variable groups containing unlabelled (`*` or blank) columns
  become named signals. Aggregate selections are retained as metadata.
- Ungrouped unlabelled runs become `signal_<first-column>` channels. When no
  unlabelled signal columns exist, the complete matrix becomes one signal.
- Remaining labelled columns become targets; duplicate names get a column
  suffix. This is a mapping convention, not a claim about their modelling role.
- The vendor float32 missing sentinel `-9.973e23` becomes NaN in signals and
  JSON null in targets. Records carry missing counts and quality flags.
- Metadata includes original variable labels, zero-based signal-column indices,
  sample/variable groups, vendor group flags and the current sample descriptor.
  Dataset-wide raw header, settings and column descriptor words are retained
  under `vendor_dataset` on the first record to avoid repeating a large table.
- Axes use zero-based indices and signal types are `unknown`, with provenance
  warnings: the observed labels contain no physical calibration or units.

## MATLAB exports

The existing `fmt-matlab` reader also handles a single numeric matrix accompanied
by `VarLabels0` and `ObjLabels` character matrices. It selects the matrix by
matching dimensions rather than by filename. MATLAB exports omit variable
groups: unlabelled columns remain one or more contiguous unknown signals.
They do not inherit NIR/NMR boundaries from an adjacent `.00D` file.

## Validation and limits

The paired private corpus is kept under `samples_local/unscrambler/` and
`samples_local/matlab/`. Every value is checked across both readers when these
files are available. Independent SciPy conformance tests check the export;
synthetic Rust tests cover group mapping, column order, missing values,
truncation, invalid counts/selections, compressed MAT and both MAT byte orders.

Other binary revisions, design/model files, multiple datasets, overlapping leaf
signal groups and ambiguous MATLAB matrices return explicit errors. Unknown
vendor descriptor semantics and wavelength/time calibration remain unmapped.
